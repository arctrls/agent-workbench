# 동일 환경에서 OpenAI 계정을 전환하는 계획

## 범위

같은 컴퓨터, OS 사용자, 홈 디렉터리, 프로젝트와 설치된 앱을 유지하고 OpenAI 로그인 계정만 변경한다. 새 장비 복원이나 프로젝트 재복제는 포함하지 않는다.

개인/프로젝트 스킬, 프롬프트, 전역 지침과 로컬 설정은 기존 파일을 계속 사용한다. 계정 전환을 위해 이 저장소의 sync를 실행하거나 Git에서 제외된 프로젝트 파일을 복원할 필요는 없다. 로컬 파일 유지와 새 계정의 기능 허용 여부는 구분한다. [설정 위치](https://learn.chatgpt.com/docs/config-file/config-basic), [인증과 로그아웃](https://learn.chatgpt.com/docs/auth)

## 계정 전환 절차

1. 전환 전 개인 스킬·프롬프트·플러그인·MCP 목록과 필요한 설정을 비교 기준으로 기록한다. 개인 서비스 연결 목록과 인증 자료는 공개 저장소에 넣지 않는다.
2. 기존 로컬 파일과 설치를 유지하고 새 계정으로 로그인한다. 사용하는 앱·CLI·IDE에서 실제 계정과 워크스페이스를 확인한다. CLI와 IDE는 로그인 캐시를 공유한다. [공식 인증 문서](https://learn.chatgpt.com/docs/auth)
3. 새 세션에서 개인/프로젝트 스킬 발견, 플러그인 설치·로딩·외부 서비스 연결, MCP, 모델과 승인 설정을 비교한다.
4. 실제로 누락되거나 인증 오류가 발생한 항목만 보완한다. 원격 플러그인이라고 모두 재설치하거나 MCP를 일괄 로그아웃시키지 않는다.
5. 필요한 플러그인·MCP의 읽기 작업과 기존 로컬 스킬을 실행한다. 계정 변경으로 인한 실패와 기존 환경의 의존성 오류를 구분한다.

완료 기준은 새 계정의 세션에서 필요한 스킬·플러그인·도구·모델을 사용할 수 있는지다. 회사 워크스페이스 정책이 제한하는 항목은 파일 동기화로 해결하지 않고 해당 정책과 실제 오류를 확인한다. [관리형 설정](https://learn.chatgpt.com/docs/enterprise/managed-configuration)

## 인증과 스킬의 구분

- 로컬에 직접 작성한 스킬과 플러그인에 포함된 스킬은 구분한다. 후자는 새 계정에서 해당 플러그인이 로드되는지에 영향을 받는다. [플러그인 문서](https://learn.chatgpt.com/docs/plugins)
- 플러그인의 계정 연결과 직접 설정한 MCP의 OAuth·환경변수·외부 서비스 인증은 별개의 경로일 수 있다. [MCP 인증 설정](https://learn.chatgpt.com/docs/extend/mcp)
- 로컬 Git/CLI 인증을 OpenAI 계정의 연결 상태와 동일하게 취급하지 않는다.
- 클라우드 메모리·예약 작업·대화 자료도 이전하려는 경우 별도 계정 데이터 작업으로 다룬다. 로컬 파일 검사만으로 이전 가능 여부나 완료를 판정하지 않는다.

## sync 수정 결과

계정 전환 검토 중 기존 sync가 앱이 관리하는 설정과 기본 제공 스킬을 저장소의 오래된 사본으로 덮어쓰는 문제를 확인했다. 계정 변경 자체가 실행하는 동작은 아니지만, Git hooks에서도 sync가 호출되므로 관리 범위를 좁혔다.

| 영역 | 변경한 동작 |
| --- | --- |
| config | 저장소의 features/MCP 키만 재귀 병합하고 다른 키 보존 |
| 앱 설정 | 모델·reasoning·플러그인 상태 등을 base 관리 범위에서 제외 |
| 개인 스킬 | 관리하는 각 스킬 디렉터리 내부만 동기화 |
| 기본 제공/외부 스킬 | `.system`과 저장소 밖에서 설치한 스킬 보존 |
| 삭제 | 저장소에서 없어진 스킬이나 설정 키를 홈에서 자동 삭제하지 않음 |
| dry-run | 실제 실행과 같은 변경 계획과 삭제 목록 표시 |
| 검증 | 대상 변경 전에 TOML·경로·rsync 계획 검증 |
| 설정 쓰기 | 출력 재파싱, 변경 감지, 임시 파일을 통한 원자적 교체 |

기존 Git hooks는 유지했다. 사용법과 의존성은 [README](../README.md)에 정리했다.

## 검증 및 남은 위험

2026-09-05 기준 회귀 테스트 15개로 설정 보존, 관리 범위, 삭제, dry-run, 반복 실행, 잘못된 TOML, 배열 표와 날짜, 심볼릭 링크, 동시 변경 감지와 교체 실패 시 원본 보존을 검증했다.

현재 홈에서 dry-run과 정상 실행은 모두 `No changes.`였고, 설정·지침·스킬·프롬프트의 파일 내용·권한·수정 시각이 유지됨을 확인했다.

남은 동작과 한계:

- 관리하는 스킬 디렉터리 내부는 저장소가 원본이므로 로컬에만 추가한 파일은 삭제될 수 있다.
- 관리 설정값이 바뀌어 TOML을 다시 쓸 때 기존 주석과 서식은 보존하지 않는다. 값이 같으면 파일 자체를 쓰지 않는다.
- 앱과 공통 잠금을 사용하지 않으므로 마지막 확인과 교체 사이의 짧은 동시 쓰기 가능성은 남는다.
- 설정 파일 교체는 원자적이지만 여러 스킬 파일 전체는 하나의 트랜잭션이 아니다. rsync 중 I/O 오류가 발생하면 일부 관리 파일이 갱신된 상태로 종료할 수 있다.
- 새 계정의 실제 권한·연결·동작은 그 계정에 로그인한 새 세션에서 확인해야 한다.

개인 환경의 구체적인 설치 목록과 프로젝트 상태는 Git에서 제외된 로컬 감사 기록으로 보존한다.
